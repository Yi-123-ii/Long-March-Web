# 重走长征播放与地图衔接

2026-11-04：基于主分支 `1b57947`（包含队友 PR #13、#14）。

- 剧情打开会隐藏整个地图屏幕，浏览器因此把文档滚动位置压回零。退出剧情后先恢复到 `#journey-map`，再播放跨站行进；手动返回的焦点不会再次滚动页面。
- 跨站行进保留出发前的地图镜头，从当前位置渐移，不再在首帧跳到旗帜中心；动画帧复用已测量的地图尺寸。
- 只预缓冲当前章节、已确定路线中即将播放的一个镜头，不下载尚未选择的分支或全部章节。地图初次打开仍不加载电影。
- 原先播放器设置 `preload=none`，却只在 `loadedmetadata` 后调用播放。由文字进入冷加载镜头时，这两个条件可能互相等待，导致一直停在封面。现在进入镜头前切换为 `preload=auto`，无需点击隐藏的原生播放器重试。
- 视频结束时保留末帧，等下一张静帧解码完成再切换，避免空白和旧封面闪回。
- 网页通过 `assets/journey-media.js` 使用生成的播放副本。原视频、原静帧和故事数据保留。H.264 保持 1280×720、原帧率、完整片长与原声；音频转为 AAC 96k，视频 CRF 25、峰值约 1.4 Mbps、faststart。PNG 静帧以相同尺寸导出 WebP 87。
- 13 个视频及 29 张 PNG 的网页副本合计从 53,696,603 字节减至 12,723,421 字节。构建参数、来源文件摘要和逐文件体积见 `web-media.json`。

## 弱网追加修复

用户反馈线上仍有视频与声音间断后，用 100 KiB/s、60 ms 延迟及快速进入镜头复测。
`34cfc3b` 的湘江补衣镜头在播放中仍出现 3 次缓冲，上次 2 Mbps 且等待预加载的检查未覆盖这种情况。

现在短片先完整下载为 Blob 再开始播放，等待时显示准备进度；只下载当前或即将播放的一段，取消已跳过片段的未完成请求。
缓存最多保留 3 段影片，重看直接复用，淘汰后释放 Object URL。导入片在翻书期间提前准备，不与下一个镜头同时争用带宽。
暂停、隐藏页面与跳过期间完成的下载不会触发旧片播放。

相同限速条件下，6.08 秒补衣镜头的中途缓冲为 0、掉帧为 0。代价是首次准备约 12 秒（快速点击、无缓存的测试条件）；常规阅读期间会提前下载。
这项策略解决网络供给不足造成的中途断音，不代表所有设备或视频原片自身的停顿都已排除。

## 重新生成

使用本地 FFmpeg 与 Sharp：

```text
node tools/build-journey-media.mjs --ffmpeg /absolute/path/to/ffmpeg --sharp /absolute/path/to/sharp
node --test modules/c/tests/*.test.cjs
```

生成文件使用来源与编码参数摘要命名。替换队友素材后须重新生成并同步提交映射与 `web-media.json`；回归检查会核对来源摘要，防止网页继续使用旧副本。FFmpeg、Sharp 仅用于构建，不随网站发布。
