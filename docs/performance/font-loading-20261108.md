# 全站字体加载调整

## 原因与处理

首页、长征纪事、精神传承和山河邮局曾在 `window.load` 或首次滚动后才给字体样式表设置地址，已经显示的系统字体随后被替换。重走长征直接加载字体样式表，但原有 `font-display: swap` 同样允许字体迟到后替换文字。

五页现在直接在 head 中加载同一份字体样式表，不再由导航脚本延迟设置。首屏可见文字从现有字库中单独提取，按页面预载所需分片，导航字体优先。全部首屏分片合计 125,696 字节，每页只预载自身需要的部分。字体文件沿用内容散列名，便于跨页面复用缓存。

字体使用 `font-display: optional`。正常下载时使用原有标准字体；字库未及时到达或下载失败时，当前页面保留备用字体，不在阅读中途替换。艺术题字图片、文字内容和字号均未修改，也未隐藏整页等待字体。原字库保留完整字符覆盖，输入与旧留言不会因裁剪丢字。

## 重建与检查

- `tools/subset-site-fonts.py` 生成字体分片、CSS、清单及五页的字体预载标签
- `tools/check-site-fonts.py` 核对字形轮廓、字宽、字符范围、无重叠路由及加载配置
- 构建依赖为 fonttools[woff]，可通过 `--dependencies` 指定已有依赖目录
- 更新首屏文字后重建；不要恢复 `data-site-fonts` 或等待 window.load 的逻辑

## 本轮验证

本地 Edge 浏览器分别检查五个页面的正常加载、手动扣住字体响应、字体请求失败三种情况，并复查 390px 手机布局。正常加载使用标准导航字体；延迟字库释放前后，导航、正文与按钮的文字宽度及换行一致；字体失败时文字仍可阅读。六个精神传承故事详情逐一打开并关闭，未发现脚本错误。字库检查通过 3,244 个裁剪字形与原文件的轮廓、字宽比较，完整输入字符覆盖保持不变。

这些是本地加载与故障模拟结果，不代表各地区访问 GitHub Pages 的实际下载耗时。
