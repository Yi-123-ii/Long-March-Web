# 首次访问加载优化（2026-11-09）

## 定位结果

测试使用五个全新浏览器上下文并禁用缓存，Edge 无头浏览器，1440 × 800，150 ms 延迟、200 KB/s 下载、CPU 4 倍减速，每页单独测量。下表是本地受控限速结果，不代表每位用户访问 GitHub Pages 的实际速度；当地网络与 CDN 连通性仍影响耗时。本地服务器不压缩文本，线上文本压缩和缓存也会影响结果。

| 页面 | 加载字节（前 → 后） | window.load（前 → 后） | 题字图片可见（前 → 后） |
| --- | --- | --- | --- |
| index.html | 2.19 → 1.55 MB | 11.38 → 8.10 s | 4.08 → 4.07 s |
| chronicle.html | 2.57 → 1.11 MB | 13.21 → 5.85 s | 3.26 → 2.70 s |
| modules/c/journey.html | 2.49 → 1.91 MB | 12.94 → 10.02 s | 3.36 → 3.08 s |
| inheritance.html | 2.35 → 1.48 MB | 12.18 → 7.77 s | 4.89 → 3.74 s |
| post-office.html | 1.54 → 1.23 MB | 8.14 → 6.51 s | 7.01 → 3.51 s |

字节统计取 window.load 后 500 ms 的资源记录；邮局备用字符配置在首屏后加载，可能仍在该窗口内下载。window.load 并不等于所有资源都必须等待才可操作，题字动画尚有 900 ms 的展示过程。首页题字首次可见时间基本持平，主要改善在整页传输量、请求数量与后续内容的竞争；未宣称所有页面的首次绘制时间均下降。

## 实现

- 将每页 7～18 份布局样式合并为一份，保留原始层叠顺序和资源路径，使用内容哈希更新缓存
- 首屏只解析当前网站文字需要的字体配置，完整输入字符配置拆分为 fonts-input.css，在输入框获得焦点时加载；邮局在首屏完成后提前准备，以兼容已保存留言
- 所有字体仍保持 font-display: optional，避免慢速下载完成后替换已显示的文字；字形、字宽与授权不变
- 封面与题字优先加载，下方图片在可见时才请求；动态纪事卡片和详情克隆也接入观察，保留禁用脚本时的静态图片
- 首页、纪事与地图的大图增加相同像素尺寸的 AVIF 编码，CSS 按格式支持选用并保留 WebP，邮局题字解码失败时回退原始 WebP
- 写信和剧情运行时主动更换的图片不会被延迟加载器覆盖，邮票与信纸仍在完成解码后展示，未引入模糊占位图替换完整信纸

## 后续维护

原始 CSS 仍是编辑入口，顺序记录在 tools/page-styles.json。修改后运行 npm run check 或 npm run build:styles，并提交自动更新的 assets/css/pages 与五页 HTML。npm run dev 在返回 HTML 前自动同步样式。字体重建工具也同步输出首屏与输入两个配置文件。发布静态站点前必须提交生成文件，GitHub Pages 不会替开发者执行本地构建。
