# V3.8 本地文字层级与字形审计

审计日期：2026-11-01。范围为五个页面以及 `assets/js`、`data` 中的浏览器源码。题字图片、SVG 展示字、首屏结构、四段纵向栏目和 B/C 功能不在字体修改范围内。

## 发现与修复

原来的 `wenkai-reading-*`、`noto-serif-sc-semibold-*` 并非完整中文字库，而是既有静态文字的子集。fontTools 读取实际 WOFF2 `cmap` 后发现：把各家族所有原分片合并，文楷和 Noto Serif SC 均只有 948 个 Unicode 映射；本次扫描的 906 个源码汉字中，各有 57 字缺失。缺失包括「亲、承、曾、深、春、秋、薪」，以及「京亲仅假公协卡商圈块坚基够尽市延戏承报拟探播收故昆昌春曾术案档概模深游灭烧熄燃爱版献直真研秋穷艺薪足跨踏边迹退链门」。原 Oswald 文件实际仅有 15 个映射，不能承担任意英文大小写。

V3.8 保留既有字体文件及许可证作版本留档，`fonts.css` 只注册两个新的本地文本家族。正常文本不再依赖这些旧子集，也不通过 `local()` 优先使用用户电脑上版本不明的同名字体。

| 角色 | CSS 字族 | 来源 | 实际字重 | cmap 映射数 |
| --- | --- | --- | --- | ---: |
| 段落、史料正文、信件输入、预览和阅读 | `Shanhe Reading` | 霞鹜文楷 Regular 1.530，保持原文楷阅读方向 | 400，关闭伪粗/伪斜 | 46,926 |
| 导航、按钮、筛选、状态、日期与元信息、文字小标题 | `Shanhe UI` | Noto Serif SC 2.003，保留真实可变字重轴 | 400–600，常规 400、控件 500、标题 600 | 30,928 |

`v38-reading.css` 放在既有页面样式之后，只声明 `font-family`、`font-weight`、`font-synthesis` 和相应字体变量，不改变尺寸、间距、布局或交互。覆盖限定于现有页面类和文字角色，未使用全站 `* !important`。B 的 `base.css`、`chronicle.css`、`post-office.css`、邮票/信纸/邮筒样式和浏览器脚本均不需要改动。C 的当前占位入口仅随公共文字层使用本地字体，没有新增地图、关卡或模拟游戏功能。

## 上游、许可与转换

下载前已浏览并核对下列第一方来源、字体说明与 OFL 原文：

- [霞鹜文楷官方仓库](https://github.com/lxgw/LxgwWenKai)；采用提交 `db34daf997d8f38e3f5595db0a56e00368d1323f` 的 [Regular TTF](https://raw.githubusercontent.com/lxgw/LxgwWenKai/db34daf997d8f38e3f5595db0a56e00368d1323f/fonts/TTF/LXGWWenKai-Regular.ttf) 与 [OFL 原文](https://raw.githubusercontent.com/lxgw/LxgwWenKai/db34daf997d8f38e3f5595db0a56e00368d1323f/OFL.txt)。原始版本名为 `Version 1.530; October 18, 2026`。
- [Google Fonts 的 Noto Serif SC 元数据](https://raw.githubusercontent.com/google/fonts/main/ofl/notoserifsc/METADATA.pb)；采用提交 `6c1dbe27dcf7d817d4b62cec033ba77fa8e2a5ec` 的 [可变 TTF](https://raw.githubusercontent.com/google/fonts/6c1dbe27dcf7d817d4b62cec033ba77fa8e2a5ec/ofl/notoserifsc/NotoSerifSC%5Bwght%5D.ttf) 与 [OFL 原文](https://raw.githubusercontent.com/google/fonts/6c1dbe27dcf7d817d4b62cec033ba77fa8e2a5ec/ofl/notoserifsc/OFL.txt)。源版本 `Version 2.003-H1;hotconv 1.1.1;makeotfexe 2.6.0`。

两者按 SIL Open Font License 1.1 随网站嵌入分发。随包保留 `assets/fonts/shanhe-reading-OFL.txt` 和 `assets/fonts/shanhe-ui-OFL.txt` 全文；每个新文件的来源 URL、原始 TTF 的 SHA-256、产物 SHA-256、实际字节数、cmap 数和 unicode-range 写入 `assets/fonts/manifest.json`。

文楷许可声明了保留名称，因此此网页衍生版本的 name 表主要名称改为 **Shanhe Reading**：name ID 1、2、3、4、6、16、17 均使用新的系列/样式/唯一名/全名/PostScript 名，不以原作者名为衍生字库背书，版权与许可证元数据保留。Noto Serif SC 使用 CSS 别名 `Shanhe UI`，内部保留上游名称；使用 fontTools instancer 将字重范围限定为实际需要的 400–600。

生成使用 `fonttools 4.68.0`、`brotli 1.2.1`、`zopfli 0.4.3`。上游 cmap 全部保留：先把全站源码可打印字符、常用拉丁字母和标点交集分入 common；其余实际映射按 Unicode 排序，每 4,096 个映射分片。每片以 `fontTools.subset.Subsetter`、`layout_features=['*']`、完整 name 表、`.notdef` 轮廓和 WOFF2 输出。不是按静态文案删去其余汉字；未列于 common 的新输入会自动命中 extended 字体片。

不要用历史 `tools/prepare-fonts.mjs` 重建 V3.8 字体：它生成的是早期文案子集，会覆盖这里的新字体注册与清单。此审计脚本只检查，完全不联网或改动字库。

## 覆盖、体积与加载

| 检查集 | 测试数 | 正文字族缺字 | 界面字族缺字 |
| --- | ---: | ---: | ---: |
| 18 个 HTML/JS/data 源文件全部汉字（含注释、元数据的保守超集） | 906 | 0 | 0 |
| GB2312 汉字区 | 6,763 | 0 | 0 |
| CJK 基本区 U+4E00–U+9FFF | 20,992 | 0 | 0 |
| CJK 扩展 A 区 U+3400–U+4DBF | 6,592 | 0 | 0 |
| ASCII 可打印字符 | 95 | 0 | 0 |
| 已知回归「曾亲承深篇QX龘靐齉」 | 10 | 0 | 0 |

除表内汉字外，脚本还核验了源码出现的全部可打印符号，两个家族均零缺字。测试不是依赖 `document.fonts.check()`；该 API 的返回值本身不能证明某字存在。本次逐片读取实际二进制 cmap，检查 CSS/manifest unicode-range 与实际 cmap 相等、不同片没有重叠、文件哈希与许可证存在，并检查 `fvar` 和 `OS/2` 中的真实字重。

正文字库 13 片，9,336,200 字节；界面字库 9 片，11,079,156 字节；合计 20,415,356 字节。这是保留完整上游映射的本地包体积，不是首屏下载体积。当前全站源码文字均在 common 中：正文 common 为 261,456 字节，界面 common 为 395,932 字节，两片合计 657,388 字节；新输入需要哪个 extended 片才加载哪个。旧 B 页面原有志莽行 preload 保留，可能额外加载 21,984 字节的历史字体文件，但 V3.8 文本不再使用该家族。

## 自定义输入与回退边界

邮局 textarea、署名输入、信纸缩略图、投递预览、已存信件摘要和信件详情均用同一阅读家族。输入 GB2312 常用汉字、基本区和扩展 A 的未见文案可使用本地字形；「龘、靐、齉、𠮷、𱁬、𰻞」经实际 cmap 验证在阅读字库中存在，其中的 supplementary 字符会加载对应 extended 片。

没有声称覆盖所有 Unicode。「𫶕（U+2BD95）」「𮷖（U+2EDD6）」不在此次两个本地字库中，交由所列系统中文字体及浏览器默认后备字体；操作系统也不含该字时仍可能出现缺字框。emoji（如 🙂）交给系统彩色 emoji 字体，同样不承诺跨操作系统绘制一致。UI 中出现阅读字库有而 Noto Serif SC 无的 supplementary 汉字时，先回退到本地阅读字库，再回退到系统。任何回退均不修改或过滤保存的用户文字。

## 可重复验证

环境需要 Python 3 和 `fonttools[woff]`。从项目根目录运行：

```sh
python3 tools/check-font-coverage.py
node tools/check.mjs
```

2026-11-01 实际结果：字体检查 `PASS`；18 个源码、两个家族、22 个文件的 cmap/范围/哈希/许可/真实字重检查通过，表列覆盖均零缺字。现有项目资源与脚本检查同时通过。

静态边界复核：新增覆盖层的全部声明仅为字体变量、`font-family`、`font-weight`、`font-synthesis`；对照原 V3.7 基线，浏览器脚本、data JS 及 B 的六份独立 CSS 均逐字节一致。

补充浏览器证据来源为独立的 **macOS headless Google Chrome**，不是主流程使用的 IAB 浏览器：五页在 1440×1000 视口中均无横向溢出，字体请求均为 HTTP 200，无错误字体 face；五页导航计算样式均为 `Shanhe UI` / 500。Chrome DevTools Protocol `CSS.getPlatformFontsForNode` 显示，首页章节说明、纪事摘要、传承案例段落、C 当前入口状态说明实际使用的都是自定义 `Shanhe Reading`，未混入系统字体。正文基本文字只请求两片 common；B 原有 preload 另行保留。

该独立浏览器的邮局输入实验保留原文「曾亲承深篇 QX 龘靐齉 𠮷𱁬𰻞 𫶕𮷖 🙂」，计算样式为阅读字族 400，并按输入自动请求四个相应 extended 分片，均 HTTP 200。textarea 的内部文本没有直接的 CDP 字形节点，因此不把其空的 platform-font 返回值当作字形证明；本地支持/不支持的具体字符结论以 cmap 为准。完整邮票—信纸—投递—保存—详情流程由主流程在 IAB 单独核验，本记录不冒充该交互测试。

未在 Windows、Safari 或所有移动设备上进行验证，不作跨平台完全一致的承诺。
